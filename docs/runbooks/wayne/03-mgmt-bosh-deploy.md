# Wayne mgmt-BOSH Deploy

Deploys the Wayne mgmt-BOSH director (VMID auto-assigned, IP `10.64.64.10`) from your operator Mac using `genesis deploy`. This is a **hard gate** — confirm the bastion is healthy before proceeding. The deploy invokes `bosh create-env` through the PVE CPI and takes 20–40 minutes.

---

## Prerequisites

Before starting this runbook, verify the following are complete:

- [CPI Account Setup](01-cpi-account-setup.md) — `ocfp-cpi@pve` user and `ocfp-cpi@pve!wayne` token exist in vault
- [Bastion Bringup](02-bastion-bringup.md) — bastion VM (VMID 101, `10.64.64.3`) is up, provisioned, and vault is reachable on it; PVE CPI dev tarball is extracted at `/var/vcap/store/bosh-pve-cpi/release/` on bastion
- Genesis bosh kit cloned with PVE overlay and hooks:
  - `~/w/fivetwenty/studios/ocfp/src/kits/bosh` — must include the PVE CPI overlays (`overlay/cpis/pve*.yml`), OCFP PVE config files (`ocfp/pve/`), and updated hooks (`hooks/blueprint.pm`, `hooks/cpi-config.pm`, `hooks/cloud-config.pm`)
- Deployments repo cloned at `~/w/fivetwenty/studios/ocfp/src/deployments/fivetwenty-ocfp` with `bosh/ocfp-lab-wayne-mgmt.yml` present
- Operator shell environment set:

```bash
export PVE_HOST=sm-0.lab.fivetwenty.io   # Tailscale FQDN — operator context
export PVE_NODE=pve
export PVE_TOKEN_ID=ocfp-cpi@pve\!wayne
export PVE_TOKEN_SECRET=<token-secret>
export PVE_BRIDGE=lvnet001
export PVE_STORAGE_POOL=data
export PVE_ISO_STORAGE=local
```

Confirm Tailscale is up and sm-0 is reachable:

```bash
ping -c 1 sm-0.lab.fivetwenty.io
```

## Step 1 — Change to the deployments directory

```bash
cd ~/w/fivetwenty/studios/ocfp/src/deployments/fivetwenty-ocfp/bosh
```

Confirm the env file is present:

```bash
ls ocfp-lab-wayne-mgmt.yml
```

Quick-inspect the operator-side `pve_host` override:

```bash
grep pve_host ocfp-lab-wayne-mgmt.yml
```

Expected: `pve_host: sm-0.lab.fivetwenty.io`. This value is set in `bosh-configs.cpi` so that `genesis deploy` from your Mac connects to PVE over Tailscale. The director itself uses `10.64.64.1` (the `lvnet001` bridge IP) once it is running — that override lives in `blocs/wayne-pve.yml` and does not affect this deploy step.

## Step 2 — Link the dev kit

The env file specifies `kit.name: dev`. Genesis resolves a `dev` kit from a local directory linked at `.genesis/kits/dev-bosh`:

```bash
genesis @dev:bosh link ~/w/fivetwenty/studios/ocfp/src/kits/bosh
```

Verify the link:

```bash
ls -la .genesis/kits/dev-bosh
```

Expected: a symlink pointing to `~/w/fivetwenty/studios/ocfp/src/kits/bosh`. If the `.genesis/kits/` directory does not exist yet, `genesis @dev:bosh link` creates it.

## Step 3 — Vault prep

### 3.1 Confirm safe target

Genesis reads secrets from the vault on the Wayne bastion. The `safe` CLI must target that vault before deploy:

```bash
safe targets
```

The active target (marked `*`) must point to the bastion vault at `https://10.64.64.3:8200` (or the Tailscale FQDN equivalent). If it does not, switch targets:

```bash
safe target wayne-bastion
```

Verify connectivity:

```bash
safe get secret/handshake
```

Expected: the handshake secret value. A timeout or connection refused means the vault on the bastion is sealed or unreachable — resolve before continuing.

### 3.3 Generate missing secrets

```bash
genesis secrets add ocfp-lab-wayne-mgmt
```

Genesis checks each required secret against vault. It generates any that are missing and prompts for any it cannot auto-generate. CPI secrets were already written during the CPI account setup — genesis will find them and skip prompting.

After it completes, verify no errors appear in the output. Re-run if the command exits non-zero; it is idempotent.

## Step 4 — Manifest dry-run

Generate the manifest without deploying to confirm the interpolated values look correct:

```bash
genesis manifest ocfp-lab-wayne-mgmt > /tmp/mgmt-manifest.yml
```

Inspect the key values:

```bash
grep -E "pve_host|static_ip|pve_node" /tmp/mgmt-manifest.yml | head -20
```

Expected values:

| Field | Expected value |
|---|---|
| `pve_host` | `sm-0.lab.fivetwenty.io` |
| `static_ip` / `internal_ip` | `10.64.64.10` |
| `pve_node` | `pve` |

If `pve_host` shows `10.64.64.1` instead of the Tailscale FQDN, the operator-side override in `bosh-configs.cpi.pve_host` is not being picked up. Confirm `ocfp-lab-wayne-mgmt.yml` contains the `bosh-configs` stanza from Step 1.

If the manifest contains `((` placeholders, secrets are missing. Re-run `genesis secrets add ocfp-lab-wayne-mgmt` and resolve any errors before proceeding.

## Step 5 — Deploy (HARD GATE)

> **STOP.** Confirm the following before running this command:
>
> - The dry-run manifest from Step 4 looks correct
> - Vault is reachable and `safe get secret/handshake` succeeds
> - The bastion is up and the CPI tarball is extracted at `/var/vcap/store/bosh-pve-cpi/release/`
> - No VMID conflicts in range 200+ on sm-0: `ssh root@sm-0 qm list`
> - Adequate free space on `data` pool: `ssh root@sm-0 pvesm status | grep data`
>
> Proceed only after confirming all checks above.

```bash
genesis deploy ocfp-lab-wayne-mgmt
```

Genesis prompts for confirmation before proceeding. Type `yes` to continue.

The deploy runs `bosh create-env` using the PVE CPI release tarball on the bastion. Typical duration is **20–40 minutes** depending on stemcell upload time and PVE disk allocation speed.

Watch for these stage progressions in the output:

1. `Validating stemcell...` — genesis uploads the stemcell to PVE `local` storage
2. `Creating VM for instance 'bosh/0'...` — CPI creates the director VM on PVE node `pve`
3. `Waiting for the agent on VM...` — director VM boots and BOSH agent checks in
4. `Compiling packages...` — packages compiled on the director VM
5. `Updating instance 'bosh/0'...` — director configured and started

A successful deploy ends with:

```
Deployed 'bosh' to 'ocfp-lab-wayne-mgmt'
```

## Step 6 — Post-deploy verification

### 6.1 Director info

```bash
genesis bosh ocfp-lab-wayne-mgmt -- env
```

Expected: director version, CPI name `pve`, and the director UUID. If this command times out, the director is not reachable at `10.64.64.10:25555` — see Troubleshooting.

### 6.2 Stemcells

```bash
genesis bosh ocfp-lab-wayne-mgmt -- stemcells
```

Expected: at least one stemcell row (genesis uploads the Ubuntu stemcell during the deploy via cloud-config).

### 6.3 VMs

```bash
genesis bosh ocfp-lab-wayne-mgmt -- vms
```

Expected: empty table or just the director itself. No other deployments exist at this point.

### 6.4 SSH to the director

From your operator Mac (via Tailscale to the lvnet001 network):

```bash
ssh -p 22 ubuntu@10.64.64.10
```

If SSH is blocked from your Mac directly (lvnet001 is not routed to your Mac), SSH via the bastion:

```bash
ssh -J ubuntu@10.64.64.3 ubuntu@10.64.64.10
```

### 6.5 Smoke test from bastion

SSH to the bastion and run the smoke script:

```bash
ssh ubuntu@10.64.64.3
bash ~/scripts/smoke/cf-api-check.sh
```

This script is placed by the provision step. It verifies the BOSH director API is reachable from the bastion.

## Troubleshooting

### CPI errors

If the deploy fails with a CPI error, retrieve the CPI log:

```bash
genesis bosh ocfp-lab-wayne-mgmt -- cpi
```

Common CPI errors:

- `authentication failure` — the `cpi_token_secret` at `secret/ocfp/wayne/pve` does not match the token on sm-0. Re-run Step 7 of the CPI account setup runbook and re-seed vault.
- `timeout waiting for task` — PVE API is overloaded or sm-0 is unreachable. Verify `ping sm-0.lab.fivetwenty.io` from the operator Mac.

### PVE API timeouts

Verify the operator-side `pve_host` is the Tailscale FQDN, not the internal bridge IP:

```bash
grep pve_host ocfp-lab-wayne-mgmt.yml
```

Expected: `sm-0.lab.fivetwenty.io`. The internal IP `10.64.64.1` is the director-side value used after the director is running. Using it from the Mac will fail because lvnet001 is not routed to your Mac.

### VMID collision

If the CPI reports a VMID conflict, list VMIDs in use on sm-0:

```bash
ssh root@sm-0 qm list
```

The CPI auto-assigns VMIDs starting at 200 (default `vmid_range_start` in the PVE overlay). VMIDs 100 (drgao) and 101 (bastion) are hand-assigned and outside this range. If any VMIDs ≥ 200 conflict with unrelated VMs, adjust `pve_vmid_range_start` in `ocfp-lab-wayne-mgmt.yml` under `bosh-configs.cpi` or manually clean up the conflicting VMs before retrying.

### Storage allocation failures

Check free space on the `data` lvmthin pool:

```bash
ssh root@sm-0 pvesm status | grep -E "^data|^zfs-1"
```

The director root disk requires approximately 50 GB on `data`. If space is insufficient, free space on sm-0 before retrying.

Check that the CPI account has `Datastore.AllocateSpace` on `/storage/data`:

```bash
ssh root@sm-0 pveum acl list | grep ocfp-cpi
```

If the ACL entry for `/storage/data` is missing, re-run Step 4 of the CPI account setup runbook.

### Genesis trace

Genesis writes a full trace log after every command. Review it for detailed error context:

```bash
cat ~/.genesis/mylogs/last-trace
```

The trace includes the full spruce merge output, bosh CLI invocations, and vault reads that occurred during deploy. Vault read failures appear as `spruce: merge: could not resolve (( vault ... ))`.

### Rollback

To tear down a failed or partial deploy:

```bash
genesis delete-env ocfp-lab-wayne-mgmt
```

Then on sm-0, confirm the director VM is gone:

```bash
ssh root@sm-0 qm list | grep -v "^[ ]*101 "
```

Any director VM that create-env left behind should not appear. If it does, destroy it manually:

```bash
ssh root@sm-0 qm stop <vmid> && ssh root@sm-0 qm destroy <vmid> --purge
```
